# PRD: RadioReel

## Додаток для запису інтернет-радіо з повною доступністю для скрінрідерів

---

## 1. Огляд продукту

### 1.1. Опис

RadioReel — це безкоштовний портативний додаток для Windows для запису музики з інтернет-радіостанцій з **повною доступністю для скрінрідерів** (NVDA, JAWS, Narrator та ін.).

### 1.2. Проблема

Більшість існуючих програм для запису інтернет-радіо не забезпечують належної доступності для користувачів зі зниженим зором. Елементи інтерфейсу не мають належних доступних міток, навігація клавіатурою обмежена, а скрінрідери не можуть коректно прочитати стан елементів.

### 1.3. Цільова аудиторія

- Користувачі зі зниженим зором, що використовують скрінрідери
- Усі користувачі, хто бажає записувати інтернет-радіо на Windows
- Користувачі, яким важлива портативність додатку (флешка, без інсталяції)

### 1.4. Ключові принципи

- **Доступність понад усе** — кожен елемент UI повинен бути доступний для скрінрідерів
- **Портативність** — один EXE файл, без інсталяції, усі дані поряд
- **Простота** — інтуїтивний інтерфейс, зрозумілий для незрячих користувачів

## 2. Платформа та розгортання

### 2.1. Цільова платформа

- **ОС:** Windows 11+ (тільки Windows)
- **Архітектура:** x64 (основна), x86 (опціонально)

### 2.2. Спосіб розповсюдження

- **Portable режим** — єдиний EXE файл
- Не потребує інсталяції
- Не потребує прав адміністратора
- Може запускатися з флешки або будь-якої папки
- Усі дані (налаштування, бази даних, записані файли) зберігаються **локально поряд з EXE**
- **Автооновлення**: не передбачено (портативна програма оновлюється шляхом заміни EXE користувачем вручну)

### 2.3. Структура файлів

```
RadioReel/
├── radioreel.exe                        # Основний виконуваний файл
├── radioreel_settings.json              # Глобальні налаштування програми (мова, тема, пристрій, хоткеї тощо)
├── profiles/                      # Профілі користувача
│   ├── Default.rrprofile         # Вбудований профіль за замовчуванням (JSON)
│   └── My Profile.rrprofile      # Додаткові користувацькі профілі (JSON)
├── logs/                          # Логи програми
│   └── radioreel.log
└── recordings/                    # Записані файли (за замовчуванням)
    ├── Station Name/
    │   ├── Artist - Title.mp3
    │   └── ...
    └── ...
```

## 3. Вимоги до доступності (Accessibility)

### 3.1. Загальні вимоги

- **Повна підтримка скрінрідерів:** NVDA, JAWS, Windows Narrator
- Використання нативних Windows Accessibility API (UI Automation / MSAA)
- Усі елементи інтерфейсу повинні мати:
  - Accessible Name (назва)
  - Accessible Role (роль)
  - Accessible State (стан)
  - Accessible Description (опис, де потрібно)
- Повна навігація клавіатурою (Tab, Shift+Tab, стрілки, Enter, Space, Escape)
- Логічний порядок фокусу (Tab Order)
- Видимий індикатор фокусу для кожного елемента

### 3.2. Скрінрідер — специфічні вимоги

- **Оголошення змін стану:** коли починається/зупиняється запис, скрінрідер повинен оголосити це
- **Live regions:** зміна назви треку, що грає, повинна оголошуватися автоматично
- **Таблиці та списки:** правильна навігація по рядках/стовпцях
- **Прогрес-бари:** озвучування відсотка завершення (конвертація, завантаження)
- **Контекстні меню:** повністю доступні з клавіатури
- **Діалогові вікна:** модальні діалоги з правильним фокусом
- **Гарячі клавіші:** глобальні та локальні хоткеї для усіх ключових дій
- **Автоматичне оголошення:** повідомлення про зміну треку, помилку з'єднання тощо

### 3.3. Стандарти доступності

- Відповідність WCAG 2.1 рівень AA (адаптовано для десктопного ПЗ)
- Microsoft Accessibility Guidelines для Windows-додатків
- Повна підтримка UI Automation

## 4. Функціональні вимоги

### 4.1. Запис інтернет-радіо (Core)

#### 4.1.1. Одночасний запис кількох потоків
- Запис необмеженої кількості потоків одночасно
- Підтримка форматів: MP3 (Icecast/SHOUTcast), AAC
- ~~Підтримка HLS (HTTP Live Streaming, `.m3u8`)~~ — **поза scope v1** (HLS потребує окремої реалізації playlist-поллера та сегментного downloader, що виходить за рамки першої версії)
- Відображення статусу кожного потоку (запис, зупинено, помилка, очікування)
- Автоматичне перепідключення при втраті з'єднання
  - Налаштування: максимальна кількість спроб (0 = нескінченно)
  - Налаштування: інтервал між спробами (секунди)

#### 4.1.2. Збереження потоку на диск
- Збереження потокового файлу (весь потік як один файл)
- Збереження окремих треків (за метаданими)
  - Опція: зберігати тільки повні пісні (пропускати перший неповний трек)
  - Опція: видаляти файл потоку після зупинки запису

#### 4.1.3. Розділення треків
- Автоматичне розділення потоку на окремі треки виключно за метаданими (ICY metadata)
- Пропуск коротких пісень (реклама): налаштування мінімальної тривалості

#### 4.1.4. Іменування файлів
- Шаблони для імен файлів із змінними:
  - `%a` — артист
  - `%t` — назва треку
  - `%l` — альбом
  - `%s` — назва станції
  - `%n` — номер треку
  - `%d` — дата
  - `%time` — час
- Окремі шаблони для:
  - Повністю записаних треків
  - Неповних треків (суфікс `_incomplete`)
  - Файлів потоку
- Налаштування: папка для збереження
- Ієрархія папок через `\` в шаблоні (напр. `%s\%a - %t`)
- **Санітизація**: заборонені в Windows символи (`\ / : * ? " < > |`) замінюються на `_`; пусті пробіли (початок/кінець назви) видаляються
- **Колізії**: якщо файл з такою назвою вже існує, додати числовий суфікс `_2`, `_3` тощо (без перезапису)
- **Кодування ICY**: спробувати UTF-8, при помилці — latin-1 (ICY-метадані технічно latin-1, але на практиці часто UTF-8)

### 4.2. Автоматичний запис (Wishlist)

#### 4.2.1. Список бажань (Wishlist)
- Список бажаних пісень/артистів для автоматичного запису
- Коли пісня зі списку виявлена на потоці — автоматично почати запис
- Підтримка wildcard-символів: `*` (будь-які символи), `?` (один символ)
- Опція: мінімальний бітрейт для автоматичного запису
- Опція: формат потоку для автоматичного запису (MP3/AAC/будь-який)
- Опція: видаляти з wishlist після запису
- Опція: додавати записані треки в ignorelist

#### 4.2.2. Список ігнорування (Ignorelist)
- Глобальний ignorelist — пісні, які ніколи не зберігати
- Локальний ignorelist — per-stream ігнорування
- Автоматичне додавання записаних треків до ignorelist (опція)

#### 4.2.3. Списки (Lists)
- Wishlist (бажані) — автоматичний запис
- Ignorelist (ігноровані) — пропуск збереження
- Імпорт/експорт у текстовий файл
- Імпорт з m3u/pls плейлістів

### 4.3. Програвач (Player)

#### 4.3.1. Відтворення потоків
- Прослуховування потоку в реальному часі
- Вибір пристрою виведення звуку
- Регулювання гучності
- Пауза / зупинка / відновлення

#### 4.3.2. Відтворення записаних файлів
- Програвання записаних файлів MP3/AAC
- Базові контролі: відтворення, пауза, зупинка, перемотка
- Відображення прогресу

#### 4.3.3. Доступність програвача
- Гучність: доступна через скрінрідер (оголошує рівень у відсотках)
- Прогрес: доступний через скрінрідер (оголошує позицію)
- Усі кнопки з чіткими мітками
- Повідомлення про зміну треку (live region)

### 4.4. Заплановані записи (Scheduled Recordings)

#### 4.4.1. Створення та редагування розкладу
- Прив'язка до конкретного потоку зі списку
- Тип запису:
  - **Одноразовий** — виконується один раз у вказаний день та час
  - **Повторюваний** — повторюється щотижня у вказаний день тижня
- Параметри запису: день тижня, час початку (HH:MM), тривалість (хвилини)
- Опціональна назва запису (для відображення в інтерфейсі)
- Можливість вимкнути запис без видалення

#### 4.4.2. Виконання розкладу
- Планувальник перевіряє час кожну хвилину (без окремих системних задач — все всередині процесу)
- **Часовий пояс**: використовується локальний час системи (без UTC-конвертації, оскільки Portable-програма завжди запускається локально)
- При настанні часу запису — автоматично запустити запис потоку
- Після закінчення тривалості — автоматично зупинити запис цього потоку

#### 4.4.3. Конфлікти та особливі ситуації

| Ситуація | Поведінка |
|----------|-----------|
| Потік уже записується вручну | Планувальник не запускає новий запис; після закінчення тривалості розкладу — не зупиняє ручний запис |
| Два заплановані записи на той самий час і потік | Виконується перший (за порядком у списку); другий ігнорується з попередженням у лозі |
| Програма була вимкнена під час запланованого запису | Пропущений запис не відновлюється; додається запис у лог: `[ScheduledRecording] Missed: <name> at <time>` |
| Потік недоступний при старті за розкладом | Запускається з тією самою логікою автоперепідключення, що й ручний запис |
| Тривалість закінчилась, але трек ще пишеться | Поточний трек дописується до кінця (зміна метаданих), після чого запис зупиняється |

#### 4.4.4. Доступність та UI
- Заплановані записи відображаються у вигляді доступної таблиці (Tab: вкладка розкладу або у налаштуваннях)
- Скрінрідер оголошує: "Плановий запис розпочато: <назва потоку>" (assertive live region)
- Скрінрідер оголошує: "Плановий запис завершено: <назва потоку>"
- Усі елементи форми редагування мають accessible labels

### 4.5. Браузер потоків (Stream Browser)

#### 4.5.1. Пошук станцій
- Пошук за назвою, URL, жанром
- Фільтрація за форматом (MP3/AAC)
- Фільтрація за мінімальним бітрейтом
- Індикація якості метаданих (чи надсилає станція інфо про треки)
- Перегляд результатів у вигляді доступної таблиці

#### 4.5.2. Джерела каталогу станцій
- Інтеграція з Radio Browser API (radio-browser.info) — відкрите API
- Можливість додавання станцій вручну за URL
- Підтримка URL-адрес: пряме посилання, m3u, pls, asx плейлісти
- HTTP Basic Auth для захищених потоків (напр. `http://user:pass@host/stream`) — опціонально
- HTTP Proxy (налаштування в налаштуваннях) — опціонально

### 4.6. Управління збереженими піснями (Saved Songs)

- Список усіх записаних файлів
- Сортування, фільтрація, пошук
- Позначки: автозапис (wishlist), обрізано (ножиці), фіналізовано (галочка)
- Контекстне меню:
  - Відтворити
  - Редагувати теги
  - Додати/видалити з wishlist/ignorelist
  - Копіювати/вирізати файл
  - Перейменувати
  - Видалити / в кошик
  - Показати в провіднику
  - Властивості файлу
- Імпорт файлів / папок

### 4.7. Теги (Tags)

- Запис ID3v2 тегів для MP3
- Запис тегів для AAC
- Поля: артист, назва, альбом, жанр, номер треку
- Опція: автоматична корекція регістру (Artist - Title)
- Видалення небажаних символів з імен файлів

### 4.8. Постобробка (Postprocessing)

#### 4.8.1. Конвертація
- Конвертація записаних файлів в інший формат (через Windows Media Foundation)

#### 4.8.2. Виконання зовнішніх скриптів
- Запуск зовнішніх програм після запису
- Налаштування аргументів командного рядка
- Таймаут виконання (120 секунд за замовчуванням)
- Черга постобробки (порядок виконання)

### 4.9. Налаштування планових записів (Scheduled Recordings)

- Запис за розкладом (день тижня, час)
- Одноразовий або повторюваний запис
- Для конкретних потоків

### 4.10. Загальні налаштування

#### 4.10.1. Програма
- Автозапуск з Windows (опціонально; запис в `HKCU\Run` — при запуску з USB буква диску може змінитись — програма попереджає про це)
- Згортання до системного лотка
- Запам'ятовування потоків, що записувалися при виході
- Відображення назви треку в заголовку вікна
- Сповіщення при зміні треку (popup)
- Зупинка запису при низькому місці на диску (налаштування порогу ГБ)
- Дія при подвійному кліку на потоці (запис / відтворення)

#### 4.10.2. Обмеження смуги пропускання
- Ліміт пропускної здатності для записів (кБ/с)
- Попередження при перевищенні ліміту

#### 4.10.3. Гарячі клавіші (Hotkeys)
- Глобальні гарячі клавіші (працюють навіть коли вікно не у фокусі)
- Налаштовувані для:
  - Старт/зупинка запису
  - Відтворення/пауза
  - Наступний/попередній потік
  - Збільшити/зменшити гучність
  - Показати/приховати вікно

#### 4.10.4. Профілі

**Профіль** — іменований набір даних, що визначає конкретний сценарій використання програми (наприклад: "Музика", "Новини", "Робочі станції"). Перемикання профілю змінює лише per-profile дані, не торкаючись глобальних налаштувань програми.

**Глобальні налаштування** (зберігаються в `radioreel_settings.json`, спільні для всіх профілів):
- Мова інтерфейсу та тема оформлення
- Пристрій виведення звуку
- Гарячі клавіші
- `minimizeToTray`, `showTrayNotifications`
- Поріг попередження про низький рівень диску
- Ім'я активного профілю (`activeProfile`)

**Per-profile дані** (зберігаються у файлі `.rrprofile`, окремо для кожного профілю):
- Список потоків (`streams`) з per-stream ignorelist
- Wishlist та глобальний ignorelist
- Заплановані записи (`scheduledRecordings`)
- Налаштування запису (`defaultOutputDir`, `fileNameTemplate`, `incompleteFileNameTemplate`, `streamFileNameTemplate`, `skipShortTracksMs`)
- Налаштування постобробки
- Рівень гучності програвача (`playerSession.volume`)
- Список збережених треків (`savedTracks`)
- URL потоків, що записувались при останньому виході (`activeRecordingUrls`)

**Операції з профілями:**
- Профіль за замовчуванням — вбудований профіль `Default.rrprofile` з базовими налаштуваннями; не може бути видалений
- При запуску програми автоматично завантажується останній активний профіль (ім'я зберігається в `radioreel_settings.json`)
- Експорт профілю у файл `.rrprofile` (JSON) — містить лише per-profile дані
- Імпорт профілю з файлу
- Копіювання профілю
- Видалення профілю (крім `Default`)

#### 4.10.5. Логування
- Запис подій у лог-файл (`logs/radioreel.log`)
- Всі події пишуться в єдиний файл; у повідомленнях вказується назва потоку: `[StationName] ...`
- Логуються: підключення, помилки, записані треки
- Ротація логів (опціонально)

#### 4.10.6. Теми оформлення

- Підтримка світлої (Light) та темної (Dark) висококонтрастних тем
- Автоматичне визначення поточної теми Windows:
  - Зчитується через реєстр `HKCU\Software\Microsoft\Windows\CurrentVersion\Themes\Personalize\AppsUseLightTheme`
  - При неможливості визначення — fallback на темну тему
- Налаштування теми зберігається у `radioreel_settings.json` зі значеннями: `"auto"`, `"dark"`, `"light"`
- За замовчуванням — `"auto"` (слідувати за темою Windows)

### 4.11. Командний рядок

- `-datadir [PATH]` — каталог для даних
- `-tempdir [PATH]` — каталог для тимчасових файлів
- `-profile [NAME]` — використати вказаний профіль замість останнього обраного
- `-minimize` — запуск згорнутим
- `-r [URL]` — записати потік
- `-p [URL]` — програти потік
- `-sr` — зупинити запис
- `-sp` — зупинити відтворення
- `-wishadd [TITLE]` — додати до wishlist
- `-wishremove [TITLE]` — видалити з wishlist

### 4.12. Локалізація

- Англійська та українська мови
- Мова визначається автоматично при першому запуску на основі системних налаштувань Windows і записується у файл налаштувань (напр., `"language": "uk-UA"` або `"language": "en-US"`)
- Будь-яка наступна зміна мови також зберігається в `radioreel_settings.json`
- Якщо автоматичне визначення не вдалось або вказана локалізація відсутня — fallback на англійську мову

## 5. Нефункціональні вимоги

### 5.1. Продуктивність

- Програма повинна стабільно записувати 20+ потоків одночасно
- Мінімальне споживання RAM (< 200 МБ при 20 потоках)
- Мінімальне навантаження на CPU
- Швидкий старт (< 3 секунди)

### 5.2. Надійність

- Автоматичне перепідключення при обривах
- Збереження стану при аварійному завершенні
- Коректне завершення запису при закритті програми
- Валідація цілісності записаних файлів
- Неповні файли (перерваний запис): зберігати з суфіксом `_incomplete`; не видаляти автоматично
- Один екземпляр (single-instance): повторний запуск передає аргументи першому екземпляру процесу (через Named Pipe) та завершується

### 5.3. Безпека

- Підтримка HTTPS/TLS потоків
- Безпечне зберігання даних (локально, без передачі на зовнішні сервери)
- Жодні особисті дані не збираються та не надсилаються; анонімні пошукові запити до Radio Browser API не містять ідентифікаторів користувача

### 5.4. Розмір

- Один EXE файл, ≤ 80 МБ (self-contained .NET 10 + WPF із триммінгом та зжаттям)
- Мінімальні зовнішні залежності (бажано zero dependencies)

### 5.5. Сумісність

- Windows 11 (build 22000+)
- Скрінрідери: NVDA 2023+, JAWS 2023+, Windows Narrator

## 6. Формат зберігання даних

### 6.1. Глобальні налаштування (`radioreel_settings.json`)
- JSON формат, людиночитабельний (відформатований)
- Містить лише налаштування, що стосуються **всієї програми** незалежно від профілю:
  - мова, тема, поведінка вікна, пристрій виведення, хоткеї, поріг диску
  - ім'я активного профілю (`activeProfile`)

### 6.2. Профіль (`.rrprofile`)
- JSON формат, людиночитабельний
- Зберігається в папці `profiles/` поряд з EXE
- Повністю портативний — описує конкретний сценарій запису
- Містить per-profile дані:
  - список потоків та їх per-stream ignorelist
  - wishlist та глобальний ignorelist
  - заплановані записи
  - налаштування запису (папка, шаблони, тривалість фільтру)
  - налаштування постобробки
  - гучність програвача
  - список збережених треків

### 6.3. Лог (`logs/radioreel.log`)
- Текстовий файл
- Ротація логів (опціонально)

## 7. Глосарій

| Термін | Визначення |
|--------|-----------|
| ICY Metadata | Метадані в протоколі ICY (Icecast/SHOUTcast), що містять інфо про трек |
| Wishlist | Список бажаних треків/артистів для автоматичного запису |
| Ignorelist | Список треків, які слід ігнорувати (не зберігати) |
| Portable | Портативний — не потребує інсталяції, працює з будь-якої папки |
| Скрінрідер | Програма екранного читання для незрячих користувачів (NVDA, JAWS) |
| ID3 | Стандарт метаданих для MP3 файлів |
| Stream Browser | Каталог інтернет-радіостанцій з можливістю пошуку |
| Postprocessing | Автоматична обробка записаних файлів після збереження |
